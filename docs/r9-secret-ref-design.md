## 1. 问题与目标

现状：AI 读服务器文件时碰到 key / token / 密码，`guard.sanitize` 会把值**打码**——防住了泄漏，
但也防住了**使用**：AI 想用这个 token 调接口、想改含密码的配置时，拿到的是 `[REDACTED]`，只能举手让用户手工干。

**目标**：AI 永远看不到明文，但能用**引用**操作敏感资源——
「知道它在哪里、能指挥它被使用、看不到它是什么」。

非目标（明确不做）：
- 不做通用密钥管理器（不替代 vault 的角色，vault 仍是桌面端 SSH 凭据的家）
- 不解决"AI 拿到引用后把**文件内容整体**外传"这类间接泄漏（见 §6 残余风险）

## 2. 核心思想：句柄间接引用（Handle Indirection）

```
AI 的世界                        受控层（ServerDesk）              服务器
─────────                        ────────────────────              ─────────
"SD_SEC_a7f3 存在一个 token，  ──► 映射表：handle → 临时文件路径   /run/serverdesk-secrets/
   用 $SD_SEC_a7f3 引用它"          使用策略（TTL/服务器/操作）      a7f3  (0600, tmpfs)
"请执行 curl -H "Auth: Bearer    ──► 校验 handle → 命令包装注入：
   $SD_SEC_a7f3 …"                    export SD_SEC_a7f3="$(cat <路径>)"
                                 ──► 审计记 handle，不记值
```

三条铁律（写进代码不变式 + 测试）：
1. **明文永不进入 AI 可见面**：命令文本、返回输出、审计、日志、AI 审查提示词里只出现 handle。
2. **句柄 = 权限**：无 TTL 过期即失效；换服务器无效；每会话新句柄。
3. **可撤销**：用户可随时删除任一句柄（服务器侧临时文件立即删除）。

## 3. 架构选型

| 方案 | 明文落点 | 优点 | 缺点 | 结论 |
|---|---|---|---|---|
| A. 服务器侧临时文件 | 服务器 `/run/serverdesk-secrets/`（tmpfs，0600） | 放 tmpfs 重启即消失；明文不出服务器；多次使用不重复注入 | 需在服务器创建/清理文件；目录需防其他用户读 | ✅ **推荐** |
| B. 桌面端注入 | 桌面内存 → SSH 通道 → 远端 shell | 实现最简 | 明文过桌面与通道；若进命令行参数则 `ps` 可见 | 否 |
| C. 环境变量注入（配合 A） | 远端进程环境 | 命令文本里只有 `$SD_SEC_xxx`；`ps` 看不到值 | `/proc/<pid>/environ` 同 uid 可读 | ✅ 作为 A 的**注入方式** |

**选型 = A + C**：映射表**权威副本在桌面端**（加密，vault DEK 加密落库），
**明文副本以 0600 权限落在目标服务器 tmpfs**，命令执行时由 ServerDesk 生成的
包装前缀以**环境变量**方式解引用——明文不进命令文本、不进 `ps`、不进 AI 视野。

为什么映射表权威副本在桌面端而不是服务器：服务器上的临时文件只承载**值**，
句柄→文件路径→策略的映射由桌面端管理，撤销/TTL/审计都在桌面端闭环，
服务器侧不需要也不应该有一个"AI 可读的映射表文件"。

## 4. 生命周期

```
① 注册 ──► ② 授予 ──► ③ 使用 ──► ④ 过期/撤销
```

| 阶段 | 行为 |
|---|---|
| ① 注册 | 两种来源：**自动**——AI 读取输出被 `sanitize` 命中时，截获原文登记 handle 并在回复中告知 AI「检测到凭据，已登记为 $SD_SEC_xxxx，可用引用代替」（可开关）；**手动**——用户在 UI 登记文件路径或直接录入值 |
| ② 授予 | 桌面端把明文经既有 SSH 通道写入 `/run/serverdesk-secrets/<handle>`（0600，属主=连接用户）；映射入库（加密） |
| ③ 使用 | AI 命令含 `$SD_SEC_xxxx` → 校验（存在/未过期/本服务器）→ 命令前注入 `export SD_SEC_xxxx="$(cat /run/serverdesk-secrets/xxxx)"` → 执行 → 审计记 handle |
| ④ 过期/撤销 | TTL 默认 15 分钟（可配）；会话结束、连接断开、用户删除 → 立即删除远端文件 + 本地映射；后台任务每分钟清扫过期项 |

## 5. AI 视角示例

```
AI:  read_file /opt/app/config.yaml
SD:  （内容中 api_key: sk-xxx 被打码为 [REDACTED:SD_SEC_a7f3]）
     检测到敏感值，已登记引用：$SD_SEC_a7f3（TTL 15 分钟）。
     你可以在命令中以 $SD_SEC_a7f3 引用它，明文不会展示给你。

AI:  exec_command: curl -s -H "Authorization: Bearer $SD_SEC_a7f3" https://api/health
SD:  （命令注入 export 后执行；输出脱敏照常；审计记 handle=a7f3）
```

AI 若尝试 `cat /run/serverdesk-secrets/*` 或 `cat /proc/*/environ`：
命令黑名单**硬拒**（新增固定规则，不开放编辑，与泄露防护同级）。

## 6. 威胁模型与残余风险（诚实清单）

| 威胁 | 防护 | 残余风险 |
|---|---|---|
| AI 读临时文件 | 路径黑名单硬拒 + tmpfs 0600 | root 权限的 AI 命令（`sudo cat`）——需要审批的命令人工把关；TTL 限窗 |
| AI 读进程 environ | TTL 短窗 + 审计 | **无法完全封堵**：同 uid 下 `/proc/*/environ` 理论可读；缓解=短 TTL + 自动捕获的值本就匹配脱敏正则（输出再泄会被二次打码） |
| AI 把整份原文件外传 | 输出脱敏（正则命中再打码） | 非 key=value 形态的敏感块可能漏打码；属现有脱敏的固有边界，非本功能新增 |
| handle 被用于非本服务器 | 映射绑定服务器 id，跨服务器校验失败 | — |
| 服务器被入侵后从 tmpfs 抓明文 | tmpfs 重启即失 + TTL + 0600 | 内存抓取无法防（与任何 secret 文件方案同级） |

**结论**：本方案把「AI 看到明文」的窗口从"每次读到文件"压缩到"服务器 tmpfs 的短 TTL 窗口"，
并将使用方式从"复制粘贴明文"升级为"引用句柄"——是实质性提升，但**不是**绝对防护。

## 7. 与现有管线的关系

| 管线 | 关系 |
|---|---|
| guard 脱敏 | 自动捕获的源头；输出兜底；新增固定黑名单（映射目录 / environ 嗅探命令） |
| guard 命令黑名单 | 新增固定 deny：`/run/serverdesk-secrets`、`serverdesk-secrets`、`strings /proc.*environ` |
| R8 AI 审查 | 审查模型看到的是 handle（无明文）——不泄露；含 handle 的命令审查提示词不变 |
| 审计 | 每次使用记 `handle=id, server, action`；映射的创建/撤销/过期全审计 |
| 备份 | 映射表**不进**备份导出（同 API Key 的处理：临时凭据不持久化） |

## 8. UI

- **服务器详情 → 敏感引用**：当前句柄列表（来源文件 / 登记时间 / TTL 剩余 / 最后使用），单个撤销 + 全部清空
- **设置页 → AI 管线**：总开关、自动捕获开关、TTL、`/run` 目录路径（高级）
- 审批卡 AI 意见、审计页无需改动（handle 已在审计流里）

## 9. 里程碑拆分（建议 R9，约 7 人日）

| 阶段 | 交付 | 估时 |
|---|---|---|
| R9.1 | 数据模型（加密映射表）+ 手动登记 + 远端临时文件写入/删除 + 单测 | 2d |
| R9.2 | 命令解引用（export 包装）+ handle 校验（TTL/服务器）+ 固定黑名单 + 审计 | 2d |
| R9.3 | 自动捕获（sanitize 命中 → 登记）+ TTL 后台清扫 + UI 管理 + 验收文档 | 3d |

验收要点：全程 grep 不出现明文（命令文本/审计/日志/AI 提示词）；撤销后命令立即失效；
跨服务器 handle 被拒；TTL 过期自动清理；旧库升级自动建表。
