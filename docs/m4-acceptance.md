# M4 验收：加密备份导出/恢复 + 定时自动备份

> 前置：完成 M2/M3 验收（已设置主密码）。

## 两种备份形态

| | 手动导出（.sdbackup） | 自动备份（本机） |
|---|---|---|
| 加密 | 用户口令 Argon2id 派生 KEK + AES-256-GCM | 当前保险库 DEK |
| 位置 | 用户自选（保存对话框） | `<数据目录>/backups/auto-*.sdbackup` |
| 用途 | 跨机器迁移 / 异地容灾 | 防误删、数据库损坏 |
| 恢复条件 | 只需备份口令（可在新机器无主密码时恢复） | 保险库需解锁 |

文件格式：`SDBK` magic + 版本 + salt(16B) + nonce(12B) + AES-256-GCM 密文（JSON 资产载荷）。
恢复支持 **合并**（按 ID 更新/新增）与 **覆盖**（事务内清空重建，保留审计日志）两种模式。

## 自动化验证（已通过）

```bash
cargo test -p serverdesk   # backup::tests::export_roundtrip_and_wrong_password
# 覆盖：导出→正确口令读回→错误口令拒绝→文件确为密文（无明文主机）→合并恢复
```

## 验收步骤

| # | 步骤 | 预期 |
|---|---|---|
| 1 | 解锁应用 →「备份恢复」页 | 三张卡片：导出 / 恢复 / 自动备份 |
| 2 | 填备份口令（两次）→「选择位置并导出」 | 系统保存对话框 → 导出成功提示台数与路径 |
| 3 | `xxd <备份文件> | head -1` | 开头 `SDBK`，之后为二进制密文，无明文 |
| 4 | 新增一台测试服务器 → 用同一文件「合并」恢复 | 测试服务器保留（ID 不同则新增） |
| 5 | 编辑某服务器名称 → 再「合并」恢复 | 名称被恢复为备份值（按 ID 更新） |
| 6 | 输错口令恢复 | 报「备份口令错误或文件已损坏」 |
| 7 | 「覆盖」模式恢复到已改动数据 | 数据完全回到备份时点（先自行再导出一份防误操作） |
| 8 | 自动备份卡片：开启 → 选周期/份数 → 保存 | 设置生效 |
| 9 | 「立即备份一次」 | 生成 `auto-YYYYMMDD-HHMMSS.sdbackup`，列表可见大小 |
| 10 | 多做几次后检查列表 | 只保留最近 N 份（旧文件自动裁剪） |
| 11 | 删除几台服务器 → 从自动备份「恢复（合并）」 | 服务器回来了（免口令） |
| 12 | 锁定保险库后点「立即备份一次」 | 报「保险库已锁定，本次自动备份跳过」（fail-closed） |
| 13 | 审计页 | backup_export / backup_restore / auto_backup_* 均有记录 |

## 已知边界

- 自动备份仅在本应用运行期间触发（应用退出期间不补跑）
- 定时任务巡检粒度 10 分钟：到期后最多延迟 10 分钟执行
